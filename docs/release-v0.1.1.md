# v0.1.1 安全加固与功能验证版本

## 版本定位

本版本在 v0.1.0 的二维码支付网关基础上，重点完善资金相关安全防护、运行稳定性、可观测性、部署配置和测试覆盖。系统仍然是“收款二维码 + 唯一展示金额 + 到账通知确认”的过渡方案，不替代微信或支付宝官方支付 API。

## 主要更新

- 完善回调地址 SSRF 防护：校验协议、用户信息、DNS 解析结果，并拒绝私有、回环、保留和未指定地址。
- 回调请求关闭自动重定向，发送前再次验证回调地址，降低 DNS 解析和跳转造成的内网访问风险。
- 增加独立 `FORPAY_ENCRYPTION_KEY`，生产环境拒绝默认密钥、短密钥和缺失加密密钥。
- Fernet 敏感数据加密不再只依赖会话密钥，支持独立密钥管理和后续轮换规划。
- 增加统一参数校验、HTTP 异常和未处理异常响应，避免将内部堆栈返回给客户端。
- 增加回调失败、WAF 拦截和未处理异常日志，日志中不记录密钥和完整通知原文。
- 增加 PostgreSQL 连接池大小、溢出连接数和超时配置。
- 增加 SQLAlchemy 异步引擎，并在应用退出时释放同步和异步连接池。
- 增加 Prometheus 请求总数和请求延迟指标，`/metrics` 仅允许管理员令牌访问。
- 严格限制 CORS 请求方法和请求头，禁止使用通配来源。
- 前端页面改为 React lazy 动态加载，拆分 Dashboard、订单、通道和支付页面资源。
- 增加基础 WAF 请求过滤，拦截常见 SQL 注入、脚本注入、路径穿越和编码探测载荷。
- 增加静态资源长期 immutable 缓存，支付 API、订单、二维码、管理端和指标接口统一禁止缓存。
- 将健康检查路由拆分到独立 API 模块，为后续完整路由模块化做准备。
- 增加 SSRF、更新签名、指标鉴权、WAF、checkout token 和性能基线测试。
- 单元测试覆盖率达到 66%，超过当前 60% 目标。
- 补充 Linux Docker Compose、源码部署、Nginx、安全和运维说明。

## 验证结果

- Ruff 检查通过。
- Pytest 13 项通过。
- 覆盖率 66%。
- 前端生产构建通过。
- Docker Compose 配置校验通过。
- 已通过真实 HTTP 请求验证健康检查、管理员登录、通道创建、订单创建、checkout 会话保护、指标鉴权和到账通知匹配。

## 已知限制

- Docker 构建测试受当前 Docker Hub 网络授权失败影响，容器镜像未在本机重新构建；本地 API、PostgreSQL 和 Redis 功能已完成验证。
- 当前业务路由仍以同步 SQLAlchemy 为主，异步引擎已准备但尚未完成所有业务接口迁移。
- 内置 WAF 是基础过滤器，生产环境仍应在 Nginx 或云 WAF 层增加规则。
- 正式承载资金前仍需完成 DNS 级 SSRF 出口策略、管理员 RBAC、Android 设备凭据、数据库恢复演练和并发压测。
