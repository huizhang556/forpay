# v0.1.0 首次发布说明

## 发布定位

这是 ForPay 的首个可运行原型版本，面向没有微信或支付宝官方开放 API、需要临时使用个人收款码完成订单确认的场景。系统通过唯一展示金额和手机到账通知匹配订单，不模拟或伪造官方支付接口。

## 本次提交内容

- 建立 FastAPI、React、PostgreSQL、Redis 和 Docker Compose 基础工程。
- 实现微信、支付宝静态二维码通道、二维码上传校验和私有文件读取。
- 实现订单创建、产品结算、公开支付页、订单有效期和并发金额尾数分配。
- 实现到账通知幂等、自动匹配、人工补单、支付事件记录和回调重试队列。
- 实现商户 API Key、HMAC 签名、时间戳防重放、幂等键和 Redis 分布式限流。
- 实现管理员会话、监控端令牌、请求体限制、安全响应头和回调地址基础 SSRF 防护。
- 实现订单 token 绑定的 checkout Cookie，保护二维码接口免受直接 URL 抓取。
- 实现过期订单 worker，避免已过期金额尾数长期占用。
- 实现 Ed25519 签名更新清单检查，但禁止在线自动执行远程代码。
- 补充 Linux Docker Compose、本地源码、Nginx、API、安全和运维文档。

## 已知限制

当前二维码仍然是人工上传的静态收款码，无法在没有官方 API 的情况下生成微信或支付宝官方指定金额码。二维码被可信页面展示后，无法阻止用户拍照转发；系统只能通过短有效期、唯一金额、到账匹配、通知去重和人工复核降低风险。
